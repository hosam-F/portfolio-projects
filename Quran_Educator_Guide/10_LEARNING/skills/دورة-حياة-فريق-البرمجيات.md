# مهارة تصميم وإنشاء الأنظمة — فريق البرمجيات المتكامل

## الغرض

طبّق هذه المهارة لتحويل فكرة النظام إلى منتج قابل للتطوير، مع مصدر حقيقة واحد، وتتبّع بين المتطلبات والقرارات والمصدر والاختبارات والحزم والوثائق. افصل دائمًا بين نجاح المصدر، ونجاح التشغيل، ونجاح التغليف، وجاهزية الإصدار.

## سير العمل الإلزامي

1. **ثبّت النطاق والمالك والبيئة.** افحص نظام التشغيل، الأدوات، المسار المصرح، الصلاحيات، المساحة، والقيود قبل التعديل. اقرأ `AGENTS.md` الأقرب، وأنشئ خطة وcheckpoint.
2. **اكتب وثيقة المتطلبات.** ميّز المتطلبات المؤكدة والمقترحة والمفتوحة، وحدد المستخدمين والبيانات والخصوصية والتكاملات وما هو خارج النطاق.
3. **صمّم المعمارية.** استخدم طبقات واضحة مثل Presentation → Application → Domain → Infrastructure. افصل UI عن Domain، وثبّت حدود التخزين والنسخ والاستعادة.
4. **صمّم نموذج البيانات.** عرّف الكيانات والعلاقات والقيود والترحيلات قبل التنفيذ. لا تغيّر Schema أو Domain لحل مشكلة عرض أو تغليف.
5. **صمّم الحسابات والصلاحيات.** افصل الدور الوظيفي عن مرحلة النمو. استخدم أقل صلاحية، واسم مستخدم فريدًا، وتجزئة كلمة مرور مع salt، وقفلًا مؤقتًا، وجلسة قابلة للإبطال، وسجل تدقيق لا يحتوي أسرارًا. لا تحفظ كلمات مرور صريحة.
6. **صمّم وضع البيانات.** افصل `CONTROLLED_SYNTHETIC` عن `LOCAL_PRODUCTION`. لا تخلط fixtures أو بيانات اختبار مع بيانات المستخدم. نفّذ استيراد البيانات الحقيقية بالمعاينة والنسخ الاحتياطي والتراجع وسجل المصدر.
7. **ابنِ الواجهة العربية.** استخدم RTL حقيقيًا، نظام ألوان وعناصر موحدًا، عناوين وحالات واضحة، صفحات مستقلة منطقيًا داخل MainWindow واحد عند ملاءمة ذلك، وAccessibleName لكل عنصر مهم. استخدم واجهات دخول وترحيب صريحة لا توحي بمصادقة غير موجودة.
8. **نفّذ تدريجيًا.** بعد كل تغيير شغّل compile واختبارًا مستهدفًا، ثم اختبارات التطبيق، ثم UI offscreen/runtime، ثم الحزمة. لا تستخدم Fake CRUD أو علاقات وهمية.
9. **تحقق من الوصولية.** اختبر Tab وShift+Tab وEnter وEscape وUI Automation، ثم Narrator بصورة مستقلة. لا تعتبر نجاح UI Automation دليلًا على نجاح قارئ الشاشة.
10. **غلّف وسجّل البصمات.** ابنِ One-Folder أولًا ثم Installer، وسجّل المسار والحجم وSHA-256 والبيئة ونتيجة التشغيل. لا تستبدل artifact تاريخيًا.
11. **اختبر دورة الحياة.** افصل Installer، First Run/SQLite، المسار الاصطناعي، Backup/Restore، Restart/Search، Standard User، Upgrade/Repair/Uninstall. لا تستخدم exit code وحده كدليل PASS.
12. **وثّق وسلّم.** أنشئ تقريرًا وManifest وcheckpoint وفهرس أدلة لكل مرحلة، وحدّث السجلات append-only، وأنشئ دليل الاستخدام والتطوير وخارطة الإصدار التالي.

## قواعد البيانات الحقيقية والخصوصية

لا تنشئ بيانات حقيقية أو بيانات أشخاص أو محتوى ديني أصلي من التخمين أو الإنترنت. إذا قدم المالك ملفًا حقيقيًا، ثبّت المصدر والغرض والترخيص وسياسة الخصوصية، خذ نسخة احتياطية مستقلة، اعرض معاينة الاستيراد، نفّذ validation، وسجّل rollback. امنع البيانات الشخصية من logs وscreenshots وfixtures العامة.

## قواعد التنظيف وإعادة الاستخدام

ابدأ بجرد غير تدميري. صنّف الملفات إلى `ACTIVE`, `HISTORICAL`, `ARTIFACT`, `ARCHIVE_CANDIDATE`, و`DUPLICATE_CANDIDATE`. قارن SHA-256 قبل اعتبار ملفين مكررين. انقل المرشحات إلى أرشيف مؤرخ قابل للاسترجاع، ولا تحذف ملفات أو قواعد بيانات أو حسابات نظام أو بيئات دون قائمة محددة وموافقة صريحة ومسار استعادة.

## بوابات الجودة

لا تُلغِ اختبارات سلامة البيانات أو التتبع أو الاستعادة لمجرد ضيق الوقت. يمكن تقليل التكرار مع الحفاظ على دليل مستقل لكل مخاطرة. أبقِ بوابات المحتوى والإصدار مغلقة إلى أن توجد مراجعة موثقة وتتحقق المتطلبات المستقلة. استخدم الحالات `PASS`, `PARTIAL`, `BLOCKED`, `NOT EVIDENCED`, و`NOT RUN` بدل التخمين.

## مخرجات كل مرحلة

أنشئ عادةً `REPORT.md`, و`MANIFEST.json`, و`STATE.txt`, و`EVIDENCE_INDEX.md`. يجب أن يذكر التقرير ما نُفذ، وما اختُبر، والهوية والبيئة، والبصمات، والبيانات المستخدمة، وما لا يثبته الدليل، والخطوة التالية. حدّث `PROJECT_PERMANENT_STATE.md` و`EXECUTION_SESSION_LOG.md` بالإضافة فقط.

## حزمة التسليم

سلّم المصدر المنظم، وملفات البيئة أو تعليمات إعادة إنشائها، وملفات الحزم وبصماتها، والوثائق العربية، ودليل الاستخدام، ودليل التطوير، وسجل القرارات، ومصفوفة التتبع، ومصفوفة فجوات الجاهزية، وخارطة الإصدار الثاني. اجعل الذكاء الاصطناعي تكاملًا اختياريًا معزولًا خلف interface، ولا تضف شبكة أو API أو telemetry إلى نظام Offline-first دون قرار مستقل.

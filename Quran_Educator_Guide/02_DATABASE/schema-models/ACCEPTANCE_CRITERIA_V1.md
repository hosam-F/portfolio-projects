# معايير قبول V1

## منهج الربط

لا يعد المتطلب جاهزًا للتنفيذ إلا إذا ارتبط بمعيار قبول قابل للملاحظة، ثم بحالة اختبار مستقلة. تستخدم هذه الوثيقة صيغة: `Requirement → Acceptance Criteria → Test Case → Implementation`.

## المعايير الأساسية

| ID | المتطلب | معيار القبول |
|---|---|---|
| AC-QUR-001 | مصدر القرآن | يظهر سجل المصدر مزود النص، النوع، الإصدار، الرابط، الترخيص، تاريخ التنزيل، البصمة، وحالة المراجعة. |
| AC-QUR-002 | سلامة المصدر | يرفض النظام الاستيراد عند اختلاف SHA-256 أو تغير محتوى الملف، ولا ينفذ تصحيحًا صامتًا. |
| AC-QUR-003 | تخزين النص | بعد الاعتماد، يمكن استرجاع جميع السور والآيات محليًا، مع بقاء تمثيل الآية للقراءة فقط. |
| AC-QUR-004 | الفصل الدلالي | لا يظهر التفسير أو الشرح أو التبسيط داخل حقل النص القرآني، ويظهر كل نوع بوسم مستقل. |
| AC-QUR-005 | الترخيص | يظهر إشعار Tanzil والرابط في شاشة المصدر وأي تقرير أو ملف يحتوي على النص أو جزء جوهري منه. |
| AC-SCOPE-001 | إدارة الحلقة | يمكن إنشاء حلقة ومجموعة ومعلم وطلاب وجدول، دون اتصال بالإنترنت. |
| AC-SCOPE-002 | الحضور | يمكن اختيار الحلقة والتاريخ، وتظهر قائمة الطلاب، ويسجل حاضر/غائب/متأخر/عذر، وتظهر النتيجة في التقرير. |
| AC-SCOPE-003 | الحفظ والمراجعة | يمكن تسجيل السورة/الآيات، نوع الأداء، الأخطاء، المراجعة، ومؤشر الإتقان القابل للتهيئة. |
| AC-SCOPE-004 | المنهج | يمكن ربط الهدف بالمجال الرئيسي والثانوي والوحدة والموضوع والنشاط والمصدر والعمر والتقويم دون نسخ المحتوى. |
| AC-MENTOR-001 | مسار المربي | يمكن عرض مراحل المسار، وتسجيل إتمام وحدة وشاهد وملاحظة مشرف، دون إصدار حكم آلي بالصلاحية. |
| AC-MENTOR-002 | الشواهد | يميز النظام بين الشاهد والملاحظة والتقييم البشري، ولا يحول التدبر أو الأثر إلى نسبة رقمية إلزامية. |
| AC-REPORT-001 | التقرير | يمكن إنشاء تقرير طالب وتقرير حضور وتقرير تقدم محليًا، مع تحديد الفترة والمجموعة وإظهار مصدر البيانات. |
| AC-BACKUP-001 | النسخ اليدوي | ينشئ المستخدم نسخة محلية باسم يتضمن التاريخ والإصدار، ثم يتحقق النظام من قابليتها للقراءة. |
| AC-BACKUP-002 | الاستعادة | قبل الاستعادة يطلب النظام تأكيدًا، ويحفظ نسخة أمان من الحالة الحالية، ويبلغ المستخدم بالنتيجة أو سبب الفشل. |
| AC-OFFLINE-001 | التشغيل دون اتصال | تعمل إدارة الحلقة والقرآن والمنهج والمتابعة والتقارير والنسخ المحلي عند تعطيل الشبكة. |
| AC-PRIV-001 | الحد الأدنى للبيانات | لا يتطلب إنشاء ملف الطالب بيانات صحية أو معرفًا رسميًا أو صورة، ولا يخزنها افتراضيًا. |
| AC-TRACE-001 | provenance | يمكن تتبع المحتوى من الوحدة إلى النوع والمصدر والعمل والطبعة والموضع وحالة المراجعة. |

## شروط رفض القبول

يرفض السيناريو إذا فقدت العملية مصدرها، أو خلطت النص القرآني بمشتقاته، أو اعتمدت مصدرًا دون حالة مراجعة، أو أرسلت بيانات للخارج، أو عدلت نصًا معتمدًا، أو فقدت الحالة الحالية أثناء الاستعادة، أو أصدرت حكمًا آليًا على صلاحية المربي.

## البوابات

لا تُعلن الوظيفة «مقبولة» إلا بعد نجاح اختبارها في بيئة اصطناعية، وتوثيق نتيجة الاختبار، وربطها بالمتطلب والقرار ذي الصلة.


## الصيغة التشغيلية الموحدة

كل معيار قابل للتنفيذ يجب أن يمر عبر: `Requirement → Precondition → Actor → Scenario → Expected Result → Failure Conditions → Test Case`.

|---|---|---|---|---|---|---|

## حالة التغطية

تغطي الجداول السابقة المتطلبات الحرجة لنطاق V1. تبقى المتطلبات الثانوية أو المؤجلة بحاجة إلى تفصيل عند إدراجها في خطة تنفيذ مستقلة، ولا تمنح هذه الوثيقة GO للبرمجة بمفردها.

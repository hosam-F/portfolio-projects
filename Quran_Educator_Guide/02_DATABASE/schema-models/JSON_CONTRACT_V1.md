# عقد البيانات JSON للإصدار الأول

> هذه مواصفة عقد فقط. لا تنشئ ملفات JSON تنفيذية ولا تحققًا برمجيًا في هذه المرحلة.

## الغرض

يحدد العقد شكلًا مستقرًا للتبادل المحلي والتصدير المستقبلي، مع الحفاظ على provenance، والإصدارات، والصلاحيات، وعدم اعتبار JSON مصدر الحقيقة بدل التخزين المنظم.

## الغلاف العام

| الحقل | النوع المنطقي | الإلزام | القاعدة |
|---|---|---|---|
| `version` | String | نعم | إصدار العقد، مثل `1.0`. |
| `schema_version` | String | نعم | إصدار مخطط المجال. |
| `entity` | Enum | نعم | اسم الكيان المفرد. |
| `exported_at` | DateTime | نعم في التصدير | ISO-8601 محلي/UTC موثق. |
| `identifiers` | Object | نعم | معرف السجل والنطاق. |
| `data` | Object | نعم | الحقول الخاصة بالكيان. |
| `relationships` | Array/Object | اختياري | معرفات مرتبطة لا نسخ كاملة افتراضيًا. |
| `provenance` | Object | حسب الكيان | المصدر والإصدار والمراجع. |
| `status` | Enum | نعم | حالة دورة الحياة. |
| `validation` | Object | نعم في التبادل | نتيجة الفحص ونسخة السياسة. |

## قواعد المعرفات والتواريخ

تستخدم المعرفات الداخلية الثابتة دون الاعتماد على الاسم المعروض. تستخدم التواريخ صيغة ISO-8601، ويجب التمييز بين `event_date` و`created_at`. لا يسمح العقد بتاريخ غير صالح أو بمعرف فارغ أو بعلاقة تشير إلى سجل خارج النطاق.

## provenance

يحتوي `provenance` عند الحاجة على `source_id` و`source_edition_id` و`source_version` و`source_location` و`content_type` و`review_status` و`reviewer_id` و`reviewed_at` و`license`. لا يكفي وجود رابط عام لإثبات التتبع.

## الحالات

تستخدم الحالات المنضبطة: `DRAFT`، `PENDING_REVIEW`، `APPROVED`، `PUBLISHED`، `RETIRED`، `ARCHIVED`، `REJECTED`. لا ينتقل المحتوى إلى `APPROVED` أو `PUBLISHED` بلا سجل مراجعة يناسب نوعه.

## قواعد النص القرآني

يجب أن يتضمن تبادل القرآن `quran_text_version_id` و`original_sha256` و`integrity_status`. يكون حقل النص للقراءة فقط، ولا يقبل العقد عمليات `PATCH` أو تحريرًا جزئيًا على النص المعتمد. اختلاف البصمة يجعل التبادل غير صالح ويوقف الاستيراد.

## قواعد الاستيراد والتصدير

قبل الاستيراد يتحقق النظام من `version` و`schema_version` والكيان والمعرفات والحالات وprovenance والعلاقات. يرفض الاستيراد إذا كان المصدر غير معتمد، أو كان الحقل الإلزامي مفقودًا، أو وجدت علاقة غير صالحة، أو تعارض الإصدار، أو تغير نص قرآني معتمد.

عند التصدير، تصدر البيانات وفق صلاحية المستخدم، مع إخفاء الحقول الحساسة غير المصرح بها، وإرفاق نطاق التصدير وتاريخه. لا يصدر النظام بيانات أطفال أو ملاحظات حساسة بصورة جماعية دون تأكيد وصلاحية.

## curriculum.json — مواصفة مفاهيمية

إذا استعمل تبادل منهجي مستقبلاً، يتكون من غلاف الإصدار، وقائمة `stages`، و`terms`، و`weeks` الاختيارية، و`units`، و`objectives`، و`activities`، و`assessments`، و`domains`، و`content_items`، و`provenance`. تكون العلاقات بالمعرفات، ويظل محتوى النص القرآني مرتبطًا بإصدار مصدر مستقل.

## versioning

لا يعدل سجل منشور هدميًا. ينشأ إصدار جديد، ويحتفظ التبادل بـ `replaces_id` أو `supersedes_id` عند الحاجة. لا تعني قابلية الاستيراد أن المستورد يملك صلاحية الاعتماد.

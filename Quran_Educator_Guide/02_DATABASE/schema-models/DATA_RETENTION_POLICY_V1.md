# سياسة الاحتفاظ بالبيانات V1

## الحالة

هذه سياسة تصميمية أولية. تطبق مبدأ **Minimum Necessary Data**، لكن المدد القانونية المحلية النهائية غير محددة في وثائق المشروع، لذلك تبقى المدد المقترحة بحاجة اعتماد مؤسسي/قانوني ولا تمثل رأيًا قانونيًا.

## الفئات

| الفئة | الغرض | مدة مقترحة | الوصول | الحذف | التدقيق | عند انتهاء المدة |
|---|---|---|---|---|---|---|
| Operational | تشغيل الحلقة والجدول والإعدادات | طوال الحاجة التشغيلية ثم أرشفة | Admin/Supervisor | أرشفة أو حذف بعد اعتماد السياسة | تغييرات حساسة | أرشفة ثم حذف آمن وفق القرار |
| Educational | الحضور والحفظ والمراجعة والتقدم | مدة البرنامج + فترة مراجعة مؤسسية | Teacher/Supervisor ضمن النطاق | لا حذف تاريخي صامت | نعم للتعديل بعد الإغلاق | إخفاء الهوية أو أرشفة |
| Child-related | أقل قدر من ملف الطالب والتواصل | أقصر مدة تحقق الغرض | مقيد جدًا | حذف/إخفاء بعد انتهاء الحاجة | نعم | حذف أو إخفاء مع حفظ إحصاء غير شخصي إن لزم |
| Audit | أثر الاعتماد والتصدير والاستعادة | مدة يحددها صاحب السياسة | Admin/Auditor | لا حذف عادي | ذاتي | أرشفة محمية أو حذف وفق سياسة معتمدة |
| Backup | نسخ التشغيل والاستعادة | عدد نسخ/مدة يحددها المسؤول | Backup Admin | حذف النسخ القديمة بعد تحقق البديل | نعم | حذف آمن وتسجيل النتيجة |
| Source/Provenance | التتبع والحقوق والمراجعة | طويل/حتى انتهاء الحاجة الحقوقية | Reviewer/Supervisor | لا حذف لمصدر استُخدم تاريخيًا؛ إيقاف بدل حذف | نعم | Retired/Suspended مع حفظ السجل |

## قواعد الخصوصية

لا تخزن بيانات صحية أو معرفات رسمية أو صورًا أو تسجيلات أو موقعًا أو ملاحظات أسرية غير لازمة. لا تخلط البيانات التشغيلية ببيانات المصدر. يحدد مستوى الخصوصية لكل Student وObservation وPortfolioArtifact وReport Export.

## الحذف والإخفاء

تعتمد الأرشفة أو الإخفاء بدل الحذف عندما يلزم الحفاظ على التاريخ. لا يحذف النص القرآني المعتمد أو provenance أو مراجعة المصدر من المسار العادي. أي طلب حذف لطفل أو جهة تواصل يراجع وفق سياسة المؤسسة والقانون المحلي.

## القرارات المفتوحة

تحتاج مدد الاحتفاظ النهائية، وحقوق الوصول القانونية، وآلية طلب الحذف، وأي متطلبات محلية إلى اعتماد صاحب المشروع/الجهة المختصة. لا يخمن النظام هذه النقاط ولا يحول المدد المقترحة إلى تنفيذ قبل اعتمادها.


## اعتماد Phase 3.10

يعتمد V1 مبدأ **Minimum Necessary Data** بصورة صريحة. لا تجمع المنظومة بيانات صحية أو معرفات رسمية أو موقعًا أو تسجيلات أو صورًا إلا إذا ثبتت ضرورة محددة واعتمدت لاحقًا بقرار مستقل. يعمل V1 Offline-first ولا يستخدم Cloud Sync.

تظل المدد الواردة في هذه الوثيقة مددًا تصميمية قابلة للتعديل، ولا تمثل موافقة قانونية نهائية. أي مدة أو حق وصول أو إجراء حذف يحتاج متطلبات قانونية محلية يوضع عليه `LEGAL_REVIEW_REQUIRED`.

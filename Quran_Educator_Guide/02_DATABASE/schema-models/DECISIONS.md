# سجل القرارات

## ADR-001 — Modular Monolith

**التاريخ:** 2026-08-20.  
**القرار:** اعتماد Modular Monolith للإصدار الأول.  
**السبب:** تطبيق Windows محلي يحتاج نشرًا بسيطًا وفصلًا واضحًا وقابلية اختبار.  
**البدائل:** Monolith غير منظم، Microservices.  
**الآثار:** ضرورة ضبط حدود الوحدات والاعتماديات.  
**الحالة:** مبدئي بانتظار المراجعة البشرية.

## ADR-002 — Offline-first

**التاريخ:** 2026-08-20.  
**القرار:** تعمل النواة دون إنترنت ودون API أو خدمة سحابية.  
**السبب:** حماية بيانات الأطفال واستمرارية العمل في الحلقة.  
**البدائل:** مزامنة فورية، خدمة سحابية مركزية.  
**الآثار:** النسخ والاستعادة محليان، والمزامنة المستقبلية تحتاج عقدًا مستقلًا.  
**الحالة:** مبدئي.

## ADR-003 — SQLite وSQLAlchemy

**التاريخ:** 2026-08-20.  
**القرار:** SQLite للتخزين المحلي وSQLAlchemy كطبقة وصول وORM.  
**السبب:** ملاءمة تطبيق سطح المكتب وقابلية الاختبار والترحيل.  
**البدائل:** ملفات مخصصة، محرك خادم.  
**الآثار:** يلزم تصميم فهارس وترحيلات ونسخ متسق.  
**الحالة:** مبدئي.

## ADR-004 — المحتوى كبيانات قابلة للإصدار

**التاريخ:** 2026-08-20.  
**القرار:** المنهج ودليل المربي بيانات محتوى بإصدارات ونشر، لا نصوصًا جامدة في الكود.  
**السبب:** تطوير المنهج بعد سنوات دون إعادة بناء البرنامج.  
**البدائل:** محتوى ثابت داخل المصدر، ملفات غير منظمة.  
**الآثار:** يلزم نظام حالة ونشر ومراجعة.  
**الحالة:** مبدئي.

## ADR-005 — عدم إضافة AI في الإصدار الأول

**التاريخ:** 2026-08-20.  
**القرار:** حجز `AI Services` كنقطة توسع دون تنفيذ أو إرسال بيانات.  
**السبب:** الخصوصية وتقليل التعقيد والتحقق من القيمة التربوية أولًا.  
**البدائل:** مساعد سحابي مبكر، تحليل محلي مبكر.  
**الآثار:** يحتاج التوسع المستقبلي موافقة واضحة وسياسة بيانات.  
**الحالة:** مبدئي.

## ADR-006 — الحد الأدنى من بيانات الطفل

**التاريخ:** 2026-08-20.  
**القرار:** تخزين البيانات اللازمة للتعليم والتواصل فقط.  
**السبب:** حماية الطفل وتقليل أثر أي تسرب أو فقد.  
**البدائل:** ملف شامل، تخزين وسائط افتراضي.  
**الآثار:** بعض الوظائف المستقبلية تحتاج قرارًا مؤسسيًا منفصلًا.  
**الحالة:** مبدئي.

## ADR-007 — القرآن أصل ودستور المنهج

**التاريخ:** 2026-08-21.  
**القرار:** القرآن الكريم هو الأصل المرجعي الذي تُربط به الجوانب الروحية والعقلية والبدنية والعملية والاجتماعية، وليس مادة دراسية مساوية لبقية المواد.  
**السبب:** حفظ وحدة المنهج ومنع عرض المجالات التربوية كمصادر مستقلة عن الأصل الشرعي.  
**البدائل:** عرض القرآن كمجال واحد ضمن قائمة مجالات متجاورة.  
**الآثار:** يحتاج المحتوى والمصفوفات والتقارير إلى بيان العلاقة بالمصدر المرجعي.  
**الحالة:** معتمد توثيقيًا، والتنفيذ البرمجي مؤجل.

## ADR-008 — مستويات المصادر الثلاثة

**التاريخ:** 2026-08-21.  
**القرار:** تمييز المصادر الشرعية الأصلية، والمصادر التراثية وشروح العلماء، والمصادر التربوية والعلمية الحديثة.  
**السبب:** منع الخلط بين الوحي والتفسير والشرح والطريقة التربوية والنشاط.  
**البدائل:** قائمة مصادر واحدة بلا مستوى.  
**الآثار:** يلزم سجل مصدر وتصنيف ونوع محتوى وحالة اعتماد.  
**الحالة:** معتمد توثيقيًا.

## ADR-009 — حماية النص القرآني

**التاريخ:** 2026-08-21.  
**القرار:** لا يُعدّل النص القرآني المعتمد يدويًا، ولا يُعاد صياغته أو يولد بواسطة AI، ولا يخلط بالتفسير. يُحفظ المصدر والإصدار وprovenance وchecksum وحالة الاعتماد وسجل التغيير والمراجعة البشرية.  
**السبب:** سلامة النص ومنع الالتباس بين القرآن والتفسير والرأي.  
**البدائل:** تحرير حر داخل المحتوى.  
**الآثار:** يحتاج النظام المستقبلي إلى إصدارات وفحوص سلامة ومراجعة مستقلة.  
**الحالة:** معتمد توثيقيًا.

## ADR-010 — Source Registry وContent Provenance

**التاريخ:** 2026-08-21.  
**القرار:** اعتماد سجل مصادر قابل للتوسع، وتتبع أصل لكل محتوى إلى المصدر والمؤلف والكتاب والموضع والإصدار والمدخل والمراجع وحالة الاعتماد.  
**السبب:** قابلية التدقيق وحماية الحقوق والتمييز بين النقل والتبسيط والإنشاء التربوي.  
**البدائل:** تخزين رابط حر داخل الدرس.  
**الآثار:** إضافة كيانات وسياسات ومصفوفة ربط.  
**الحالة:** معتمد توثيقيًا.

## ADR-011 — AI مساعد لا مصدر شرعي

**التاريخ:** 2026-08-21.  
**القرار:** يمكن لـ AI مستقبلًا اقتراح أسئلة أو خطط أو أنشطة أو تبسيطات، لكنه لا يولد القرآن أو الحديث، ولا يفتي، ولا يغير نصًا معتمدًا، ولا يعتمد مصدرًا شرعيًا.  
**السبب:** إبقاء القرار الشرعي والمراجعة البشرية خارج التوليد الآلي.  
**البدائل:** جعل AI مصدرًا مباشرًا للمحتوى.  
**الآثار:** كل مخرج آلي يحتاج وسمًا ومراجعة، والبيانات الحساسة لا ترسل خارجيًا افتراضيًا.  
**الحالة:** معتمد توثيقيًا، بلا تنفيذ في الإصدار الأول.

## ADR-012 — حالة المصادر الجديدة

**التاريخ:** 2026-08-21.  
**القرار:** تُسجل المصادر المقترحة في حالة «مقترح» أو «قيد المراجعة» ولا تعتمد تلقائيًا.  
**السبب:** عدم تحويل مجرد الإدراج إلى اعتماد شرعي أو تربوي.  
**الآثار:** القائمة الأولية تحتاج مراجعة بشرية متخصصة قبل استخدامها في محتوى نهائي.  
**الحالة:** معتمد توثيقيًا.

## ADR-013 — المراحل الأربع ومجالاتها

**التاريخ:** 2026-08-21.  
**القرار:** تُحفظ أسماء المراحل والمجالات التربوية كبيانات قابلة للتعديل، مع إبقاء المرحلة العمرية منفصلة عن دور المستخدم.  
**السبب:** منع الخلط بين «المربي المساعد» كمرحلة نمو و«المربي المساعد» كصلاحية تشغيلية.  
**الحالة:** يحتاج اعتماد نطاق الإصدار الأول.

## ADR-014 — Master Curriculum Taxonomy وCross-Domain Integration

**Decision ID:** ADR-014  
**التاريخ:** 2026-08-21.  
**Context:** كانت المجالات والمصادر والمحتوى موثقة، لكن احتاجت إلى تصنيف رئيسي يجعل القرآن طبقة مرجعية عليا ويمنع تكرار المحتوى بين المجالات.  
**Decision:** اعتماد `MASTER_CURRICULUM_TAXONOMY.md`، واعتماد `Primary Domain` و`Secondary Domains`، ومسار المصدر إلى الأثر، مع فصل المجال عن نوع المحتوى ومستوى المصدر.  
**Rationale:** توحيد النموذج التربوي، وإبقاء القرآن أصلًا ودستورًا، وتسهيل التوسع دون جزر أو نسخ متكرر.  
**Alternatives:** قائمة مجالات متوازية، أو ربط كل وحدة بمجال واحد فقط.  
**Consequences:** تحتاج المصفوفة وقاموس البيانات والتصميم المنطقي إلى روابط متعددة، وتحتاج البيانات غير المعروفة إلى `UNKNOWN` أو `PENDING_REVIEW`.  
**Status:** معتمد توثيقيًا، والتنفيذ مؤجل.

## ADR-015 — معيار المراجعة القابل للتوثيق

**Decision ID:** ADR-015  
**التاريخ:** 2026-08-21.  
**Context:** لا ينبغي أن يحكم النظام على العلماء أو المصادر بمعايير شخصية أو غير قابلة للتحقق.  
**Decision:** تعتمد مراجعة المصادر على صحة النص والنسبة، ومكانة المصدر في مجاله، والتوافق مع المرجعية، وجودة التحقيق، ووضوح الطبعة، وموثوقية الناشر أو المحقق، ومجال الاستخدام، ودرجة المراجعة البشرية.  
**Rationale:** قابلية التدقيق ومنع التخمين أو التعميم على المؤلفين.  
**Alternatives:** تقييم شخصي شامل للمؤلف أو حكم آلي.  
**Consequences:** قد تبقى مصادر في `PENDING_REVIEW` حتى يكتمل القرار البشري.  
**Status:** معتمد توثيقيًا.

## ADR-016 — ثلاثة جوانب كبرى مع الحفاظ على المجالات التفصيلية

**Decision ID:** ADR-016  
**التاريخ:** 2026-08-21.  
**Context:** احتاج التصنيف الستّي إلى عرض تربوي أعلى أكثر وضوحًا، مع عدم جعل القرآن مجالًا موازيًا أو حذف المجالات السابقة.  
**Decision:** تُجمع المجالات الستة تحت ثلاثة جوانب كبرى: الروحي والعقلي، البدني والعملي، والاجتماعي والمسؤولية. يبقى القرآن والمرجعية الشرعية طبقة تأسيسية فوقها.  
**Rationale:** تبسيط الرؤية التربوية مع الحفاظ على التفصيل وقابلية التتبع.  
**Alternatives:** إبقاء ستة مجالات في المستوى الأعلى، أو جعل القرآن مجالًا موازيًا.  
**Consequences:** تحتاج المصفوفة والتقارير وواجهة المنهج إلى عرض هرمي، ولا تُحذف المجالات التفصيلية.  
**Status:** معتمد توثيقيًا، والتنفيذ مؤجل.

## ADR-017 — فصل عائلة المصدر عن هرم الثقة

**Decision ID:** ADR-017  
**التاريخ:** 2026-08-21.  
**Context:** اقترح التحديث هرمًا من 0 إلى 5، بينما كانت الوثائق السابقة تستخدم ثلاثة مستويات عائلية للمصادر.  
**Decision:** يحتفظ النظام بـ `Source Level` بوصفه عائلة مصدر، ويضيف `Trust Level` من 0 إلى 5 بوصفه موقع الاستخدام/الأصل في الهرم. لا يستبدل أحد الحقلين حالة المراجعة أو الترخيص.  
**Rationale:** الاستفادة من التحديث دون محو تاريخ التصنيف السابق أو الخلط بين نوع المصدر ودرجة اعتماده.  
**Alternatives:** استبدال المستويات الثلاثة مباشرة بستة مستويات، أو استخدام حقل واحد.  
**Consequences:** تحتاج البطاقات والمصفوفة والبيانات إلى حقلي تصنيف مستقلين.  
**Status:** معتمد توثيقيًا، والتنفيذ مؤجل.

## ADR-018 — ثمانية مجالات تفصيلية ومسار صناعة المربي

**Decision ID:** ADR-018  
**التاريخ:** 2026-08-21.  
**Context:** قدمت المواصفات التفصيلية ثمانية مجالات تعليمية ومسارًا تصاعديًا لصناعة المربي، مع بقاء الجوانب الثلاثة العليا والقرآن المرجع الأعلى.  
**Decision:** اعتماد المجالات الثمانية كطبقة تفصيلية داخل الجوانب الثلاثة، واعتماد «صناعة المربي» مسارًا عابرًا للمجالات لا مجالًا تاسعًا.  
**Rationale:** يضيف دقة تربوية دون إلغاء التنظيم الثلاثي أو جعل القرآن مجالًا موازيًا.  
**Alternatives:** إبقاء ستة مجالات تفصيلية، أو جعل صناعة المربي مجالًا مستقلًا.  
**Consequences:** يلزم تعريف المجالات الفرعية وشواهد الانتقال ومسار النمو، ولا يعتمد الانتقال على العمر وحده.  
**Status:** معتمد توثيقيًا، والتنفيذ مؤجل.

## ADR-019 — علاقة الموضوع بالقرآن ليست إلزامية مصطنعة

**Decision ID:** ADR-019  
**التاريخ:** 2026-08-21.  
**Context:** قد ترتبط بعض الموضوعات بنص قرآني مباشر، أو بصلة عامة، أو تكون وسيلة تربوية/علمية دون نص مباشر.  
**Decision:** يميز النظام بين العلاقة القرآنية المباشرة والعامة وعدم وجود علاقة مباشرة، ولا يخترع آية أو ينسب نظرية حديثة إلى القرآن لملء حقل.  
**Rationale:** حماية سلامة الاستدلال ومنع التكلف في النسبة.  
**Alternatives:** إلزام كل نشاط أو موضوع بمرجع قرآني مباشر.  
**Consequences:** تحتاج المصفوفة إلى نوع علاقة، وتحتاج المراجعة إلى التحقق من سبب الربط.  
**Status:** معتمد توثيقيًا.


## ADR-020 — المصدر الرقمي التقني للنص القرآني في V1

**التاريخ:** 2026-08-21.  
**القرار:** يعتمد الإصدار الأول مصدر Tanzil Quran Text، ونوع النص Uthmani، بالإصدار 1.1 المنشور في فبراير 2021، بوصفه المصدر الرقمي التقني المقترح للنص العربي. لا يُفهم هذا القرار على أن Tanzil جهة اعتماد شرعي للمشروع؛ فاعتماد المشروع الداخلي يحتاج مراجعة بشرية مؤهلة.

**ضوابط القرار:** يحفظ الملف الأصلي كما نُزّل، ويُسجل الرابط وتاريخ التنزيل والإصدار والترخيص والبصمة SHA-256 وحالة المراجعة. لا تُجرى أي تصحيحات تلقائية على النص، وأي اختلاف في البصمة أو المحتوى يعامل كفشل سلامة واستيراد لا كخطأ يُصلح بصمت.

**الترخيص:** تشير صفحة Tanzil الرسمية إلى Creative Commons Attribution 3.0، وإلى منع تغيير النص وضرورة نسبة المصدر ووضع رابط Tanzil وإبقاء إشعار الترخيص في النسخ المطابقة أو المحتوية على جزء جوهري من النص. يجب فحص ترخيص كل ترجمة أو تفسير بصورة مستقلة.

**الحالة:** معتمد لنطاق V1 على نحو مشروط بالمراجعة البشرية النهائية قبل الإنتاج.

## ADR-021 — تخزين النص القرآني الكامل في V1

**التاريخ:** 2026-08-21.  
**القرار:** يخزن الإصدار الأول النص العربي الكامل آيةً آيةً داخل التخزين المحلي، مع الاحتفاظ بملف Tanzil الأصلي وبيانات سلامته بوصفهما أصلًا قابلًا لإعادة البناء، وعدم اعتبار تمثيل قاعدة البيانات المصدر الوحيد.

**التدفق المعتمد:** ملف المصدر الأصلي → تحقق من الإصدار والبصمة → مراجعة بشرية → استيراد مضبوط → تحقق من عدد السور والآيات والبصمات → إتاحة للقراءة فقط.

**الحالة:** معتمد لنطاق V1 على نحو مشروط باعتماد المصدر النهائي والترخيص والاختبارات.

## ADR-022 — نطاق V1: نواة تشغيل الحلقة القرآنية

**التاريخ:** 2026-08-21.  
**القرار:** يركز V1 على إدارة الحلقة والطلاب والمجموعات والمعلمين والتسجيل والحضور، والقرآن والتصفح والبحث والربط، والمنهج والأنشطة، ومتابعة الحفظ والمراجعة، ودليل المربي الأساسي مع مسار نمو موثق، والتقارير الأساسية، والنسخ الاحتياطي اليدوي والاستعادة المتحققة.

**خارج V1:** الذكاء الاصطناعي التوليدي، التدريب المتقدم للمربين، التوصيات الذكية، المزامنة السحابية، تطبيق الجوال المستقل، تعدد الفروع، التحليلات المتقدمة، التحفيز المتقدم، وإدارة المؤسسة الواسعة.

**الحالة:** معتمد لنطاق V1.

## ADR-023 — مسار صناعة المربي في V1

**التاريخ:** 2026-08-21.  
**القرار:** يمثل مسار صناعة المربي في V1 مسار نمو موثقًا لا نظام اعتماد مهني أو شرعي آلي. يستطيع المربي قراءة الوحدة وتنفيذ النشاط وتسجيل إتمامه والشواهد المرتبطة به ومراجعة تقدمه، بينما تبقى أحكام الصلاحية والاعتماد والمراجعة النهائية بشرية.

**الحالة:** معتمد لنطاق V1.

## ADR-024 — الفصل بين مرحلة المربي ودور النظام

**التاريخ:** 2026-08-21.  
**القرار:** تبقى «مرحلة المربي المساعد» جزءًا من `Mentor Path Stage`، ويستخدم النظام التقني `TRAINEE_TEACHER` للدور التشغيلي الذي يملك صلاحيات محددة. لا يجوز استخدام الاسم العربي نفسه بوصفه مرحلة نمو وصلاحية وصول.

**الحالة:** معتمد لنطاق V1.

## ADR-025 — مؤشرات التدبر والتثبيت والنمو والأثر

**التاريخ:** 2026-08-21.  
**القرار:** تمثل هذه المفاهيم في V1 بوصفها مؤشرات وشواهد ومخرجات قابلة للتوثيق، لا درجات رقمية مصطنعة. يقاس ما يمكن قياسه، ويوثق ما يمكن ملاحظته، ولا يخترع النظام رقمًا لما لا يصح اختزاله.

**التعريفات التشغيلية:** التدبر نشاط مقصود لفهم المعنى وربطه بالهداية والعمل وفق المحتوى المعتمد؛ والتثبيت ممارسات للمحافظة على إتقان المحفوظ واستدعائه؛ والنمو تغير موثق عبر الزمن؛ والأثر نتيجة أو شاهد يظهر بعد نشاط أو ممارسة.

**الحالة:** معتمد لنطاق V1، مع بقاء rubrics التفصيلية للمراجعة البشرية.

## ADR-028 — صاحب المشروع والمرجعية الملكية

**التاريخ:** 2026-08-21.

**القرار:** صاحب مشروع «دليل المربي القرآني / صُنّاع المربي والمفكر» هو **م/ حسام الجرافي**. يتولى صاحب المشروع قرارات النطاق والاعتماد، والإشراف على التطوير، والاعتماد النهائي للقرارات التوثيقية، والمرجعية في اعتماد الإصدارات ما لم يقرر خلاف ذلك.

**قواعد الحوكمة:** لا يفترض وجود مالك آخر للمشروع. ولا تمنح Manus أو ChatGPT أو أدوات الذكاء الاصطناعي أو أدوات التطوير أي ملكية للمشروع لمجرد استخدامها. يجب فصل صاحب المشروع عن المصنفات الأصلية، والمواد الخارجية المرخصة، ومساهمات الأطراف الأخرى، والأدوات المستخدمة، وبيانات المستخدمين.

**الآثار:** يعتمد `docs/IP/OWNERSHIP_REGISTER.md` بوصفه سجل الملكية الداخلي، وتخضع المواد الخارجية لسجلات المصدر والترخيص، ويحتاج أي نقل قانوني أو تسجيل رسمي إلى مستند وجهة مختصة. لا يمثل هذا القرار تسجيلًا قانونيًا ولا رأيًا قانونيًا.

**الوثائق المتأثرة:** جميع وثائق IP، و`V1_IMPLEMENTATION_GATE.md`، و`V1_SCOPE.md`، و`PHASE_3.9_IP_PROTECTION_REPORT.md`.

**الحالة:** معتمد توثيقيًا بناءً على تصريح صاحب المشروع؛ الإجراءات القانونية الرسمية غير منفذة.


## ADR-029 — المراجع البشري لمصدر القرآن في V1

**التاريخ:** 2026-08-21.

**قرار صاحب المشروع:** يصرح صاحب المشروع **م/ حسام الجرافي** بأنه المراجع البشري النهائي لمصدر النص القرآني المعتمد في الإصدار الأول V1. يؤجل إضافة مراجع بشري آخر أو لجنة مراجعة إضافية إلى الإصدار الثاني V2، ما لم يقرر صاحب المشروع خلاف ذلك.

**نطاق القرار:** هذا اعتماد حوكمي داخلي لمصدر رقمي تقني داخل المشروع، ولا يمثل فتوى أو اعتمادًا شرعيًا عامًا، ولا يجعل Tanzil جهة اعتماد شرعي. يبقى المصدر خاضعًا لسياسة Tanzil وحقوقه، وتبقى سلامة الملف والإصدار والبصمة والترخيص وشروط النسبة واجبة التوثيق.

**ضوابط التنفيذ المؤجل:** لا ينزل النص أو يستورد إلى المشروع في هذه المرحلة. عند بدء تنفيذ V1، يجب حفظ ملف المصدر الأصلي، وتسجيل الإصدار والرابط وتاريخ الاكتساب والترخيص وبصمة SHA-256، وإجراء فحص سلامة، ثم تسجيل مراجعة م/ حسام الجرافي وتاريخها ونطاقها قبل الإتاحة للقراءة فقط.

**أثر V2:** يضاف مراجع أو لجنة إضافية في V2 بقرار مستقل، ولا يعد غياب المراجع الإضافي في V1 نقصًا غير موثق بعد اعتماد هذا القرار.

**الوثائق المتأثرة:** `OPEN_DECISIONS.md`، `QURAN_SOURCE_POLICY.md`، `DATA_MODEL_V1.md`، `CONTENT_ORIGIN_REGISTER.md`، `V1_IMPLEMENTATION_GATE.md`، `PHASE_3.10_SOURCE_REVIEW_REPORT.md`.

**الحالة:** معتمد توثيقيًا من صاحب المشروع لنطاق V1.


## Phase 3.10 — قرارات الإغلاق والتحديث

### ADR-030 — اعتماد صاحب المشروع للمصنفات الأصلية في V1

يعتمد م/ حسام الجرافي المصنفات الأصلية ودليل المربي في V1 بصفته صاحب المشروع والمرجع النهائي، دون اختراع لجنة شرعية أو علمية غير معينة. يمكن إنشاء لجنة مراجعة مستقلة في V2 بقرار مستقل. هذا قرار حوكمي داخلي وليس رأيًا قانونيًا أو شرعيًا عامًا.

### ADR-031 — سياسة Minimum Necessary Data والاحتفاظ

يعتمد V1 جمع أقل قدر ضروري من البيانات، مع منع البيانات الصحية والمعرفات الرسمية والموقع والتسجيلات والصور ما لم تثبت ضرورتها وتعتمد لاحقًا. تكون سياسة الاحتفاظ قابلة للتعديل بحسب نوع البيانات، ولا توصف بالموافقة القانونية النهائية قبل `LEGAL_REVIEW_REQUIRED`.

### ADR-032 — Rubric نمو المربي

يعتمد V1 Rubric وصفيًا قائمًا على الشواهد والمؤشرات والسلوك التطبيقي والمراجعة البشرية. لا ينتج عنه اعتماد مهني أو شرعي آلي، ولا يختزل التدبر والنمو والأثر في درجة واحدة.

### ADR-033 — TRAINEE_TEACHER

يعتمد `TRAINEE_TEACHER` دورًا تشغيليًا محدودًا، منفصلًا عن مرحلة النمو التربوي. لا يسمح بتعديل النص القرآني أو مصادره، ولا يمنح صلاحيات إدارية عليا أو وصولًا حساسًا إلا بالحد الأدنى الضروري، ولا يمنح اعتمادًا شرعيًا.

### ADR-034 — ترخيص المواد الخارجية

لا يدخل تفسير أو ترجمة أو مادة خارجية إلى V1 إلا بعد تسجيل المصدر والمالك/الناشر والإصدار أو الطبعة والترخيص وتاريخ الاكتساب والبصمة عند توفر ملف وprovenance وحالة المراجعة. لا يفترض ترخيص النص القرآني ترخيص مادة أخرى.

### ADR-035 — Recovery Drill

يعتمد V1 `Manual Backup + Verified Restore`، مع هدف تصميمي أولي لاستعادة النسخة القياسية لا يتجاوز 30 دقيقة. هذا Target وليس نتيجة اختبار، ويجب قياسه فعليًا بعد البرمجة. يفشل الاسترجاع عند فشل التحقق من سلامة النسخة.

### ADR-036 — نطاق Project

يبقى مفهوم `Project` في V1 عند الحاجة التنظيمية، بينما تؤجل إدارة المشاريع المتقدمة وسير العمل متعدد المراحل والمحافظ المعقدة إلى V2، لمنع تضخيم النطاق.

### ADR-037 — التصدير الحساس

يكون التصدير في V1 محليًا فقط، ومقيدًا بالدور والنطاق، ويتطلب تأكيدًا صريحًا وسجل تدقيق، ويمنع التصدير الحساس افتراضيًا، ولا يدعم Cloud Export. يطبق Minimum Necessary Data على أي بيانات طفل.

### ADR-038 — بوابة الملكية الفكرية

تكون IP Gate في حالة `CONDITIONAL GO` تصميميًا عند اكتمال Content Origin Register وProvenance وLicense Register ومتطلبات Attribution وتحديد المصنفات الأصلية والمواد الخارجية والبرمجيات الخارجية وتراخيصها. لا تغلق البوابة قبل فحص الإصدار النهائي، ويبقى أي غموض قانوني `LEGAL_REVIEW_REQUIRED`.

تؤكد هذه القرارات أن `Design Coverage ≠ Implementation Coverage`، ولا تمنح GO للبرمجة قبل اجتياز البوابة العامة.


## ADR-3.12.12 — Controlled Installer & Clean-Machine Validation

**Decision:** اعتماد Phase 3.12.12 كمرحلة تقنية تالية مخططة، لا كإذن تنفيذ تلقائي.

**Rationale:** Phase 3.12.11 أثبتت executable one-folder في بيئة التطوير وisolated-package smoke، لكنها لم تثبت Installer أو Clean Machine أو Normal User أو Install/Upgrade/Uninstall.

**Scope:** Installer تجريبي، فصل install payload عن user-writable data، first run، SQLite، restart، report، backup/verify/restore، upgrade، uninstall/data-retention policy، payload/secret scans، checksum، وcontrolled release-candidate evidence.

**Constraints:** لا محتوى قرآني حقيقي، لا بيانات أشخاص حقيقية، لا Cloud/API/Telemetry، لا Production Migration، لا نشر، ولا تغيير للـ Content Gate أو Release Gate.

**Approval boundary:** هذا سجل تخطيط وتثبيت قرار نطاقي فقط. يبدأ التنفيذ بعد أمر مستقل من المالك م/ حسام الجرافي.


## ADR-039 — Shared Folder/HGFS Gate قبل النقل الخارجي

**التاريخ:** 2026-08-23.

**القرار:** لا يُنقل Installer إلى Windows VM النظيفة ولا تبدأ اختبارات التطبيق الخارجية حتى تعمل VMware Tools، ويظهر Shared Folder namespace داخل Guest، ويُثبت نقل ملف اصطناعي في الاتجاه المطلوب مع تطابق SHA-256. نتيجة Phase 3.12.12-B.3 الحالية هي `BLOCKED`: خدمة `VMTools` تعمل، وسائق `vmhgfs` يعمل، لكن `\\vmware-host\\Shared Folders` غير قابل للوصول و`vmware-hgfsclient` غير موجود.

**السبب:** منع اعتبار إعداد المضيف أو وجود السائق دليلًا كافيًا على قابلية النقل الفعلية داخل Guest، وحماية Clean Baseline من النقل غير المتحقق.

**الضوابط:** تبقى Shared Folder مقيدة بـ `C:\\QuranVM\\transfer` وبوضع Read-only. يمنع استخدام Registry hacks أو Drivers خارجية أو تغيير الشبكة كحل التفافي. لا ينقل Installer ولا يُشغّل قبل إغلاق بوابة النقل.

**الحالة:** `BLOCKED / HUMAN REVIEW REQUIRED FOR NEXT INFRASTRUCTURE ACTION`.

**الوثائق المتأثرة:** `PHASE_3.12.12_B3_HGFS_RECOVERY_REPORT.md`، `ROADMAP.md`، `V1_PRODUCTION_READINESS_GAP_MATRIX.md`، `TRACEABILITY_V1.md`.



## ADR-040 — حدّ Shared Folder في B.4

**التاريخ:** 2026-08-24.

**القرار:** تعتمد Phase 3.12.12-B.4 نجاح ظهور Shared Folder ونجاح HOST → GUEST مع تطابق SHA-256 كدليل جاهزية للنقل الاصطناعي أحادي الاتجاه فقط. لا يعتمد GUEST → HOST ما دامت المشاركة Read-only، ولا يجوز تغييرها إلى Writable في هذه المرحلة.

**النتيجة:** `VMTools = PASS`، `vmhgfs = PASS`، `Shared Folder namespace = PASS`، `HOST_TO_GUEST = PASS`، `SHA_MATCH = PASS`، و`GUEST_TO_HOST = BLOCKED_BY_READ_ONLY`. لذلك تبقى بوابة النقل الكامل `BLOCKED`، ولا يُنقل Installer أو يبدأ اختبار التطبيق قبل قرار مرحلة لاحقة.

**الحالة:** معتمد توثيقيًا لنطاق B.4 فقط، دون فتح Content Gate أو Release Gate.


## ADR-030 — تعليق EX-06 بسبب عطل إقلاع بيئة الاختبار

**التاريخ:** 2026-08-24.

**القرار:** تُصنَّف عملية `EX-06 — Standard User Operation` مؤقتًا كـ `BLOCKED` لأن Clean VM لم تعد تقلع بعد فشل استئناف الحالة المعلّقة، وظهور Windows Stop Code: `INACCESSIBLE_BOOT_DEVICE`. لا تُنسب هذه النتيجة إلى التطبيق قبل عزل عطل بيئة الاختبار وإعادة تشغيلها بصورة سليمة.

**حدود الدليل:** أثبتت الأدلة السابقة نجاح `EX-01` إلى `EX-05` بالبيانات الاصطناعية فقط. وثبت أن الحساب `vm1` عضو في `Administrators`، ولذلك لا يصلح دليلًا لاختبار Standard User. لم تُنفَّ دورة EX-06 بحساب قياسي مستقل، ولم يبدأ `EX-07`.

**إجراء السلامة:** لا يُحذف القرص الافتراضي أو snapshot أو ملفات `.vmdk` أو `.vmem` أو `.vmsn`، ولا تُنفّذ إصلاحات تلقائية أو تغييرات في Storage Controller قبل checkpoint وموافقة صاحب المشروع على خطة الاسترداد.

**الحالة:** `BLOCKED — ENVIRONMENT BOOT FAILURE`.

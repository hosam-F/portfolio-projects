# دليل التطوير العربي

## قاعدة العمل

ابدأ من `D:\quran`، اقرأ الحالة والقرارات، وأنشئ فرع مرحلة ومجلد build مستقلًا. لا تعدّل السجلات التاريخية. كل تغيير مهم يحتاج checkpoint ونتيجة اختبار ومسار رجوع.

## الطبقات

تضع `presentation` الواجهة وRTL والتنقل، وتضع `application` حالات الاستخدام، ويحتوي `domain` القواعد والنماذج المستقلة عن Qt، بينما تحتوي `infrastructure` SQLite وSQLAlchemy والترحيلات والنسخ والتقارير. لا تصل View إلى قاعدة البيانات مباشرة، ولا تضع منطق الأعمال في زر أو نافذة.

## المصادقة المستقبلية

يجب وضع خدمة مصادقة مستقلة بين الواجهة وطبقة التطبيق، مع repository للحسابات، ومكوّن تجزئة كلمات المرور، ومكوّن جلسة، ومكوّن سياسة قفل، ومكوّن تدقيق. يجب أن تقبل الخدمات AuthorizationContext صادرًا عن جلسة موثقة بدل السياق التجريبي الثابت. لا تضع كلمات المرور في الاختبارات أو fixtures أو logs.

## الترحيلات

أنشئ Migration صريحة لكل تغيير Schema، واختبرها على نسخة منفصلة مع backup وrollback. لا تستخدم `create_all` كبديل لترحيل إنتاجي، ولا تحذف جدولًا أو تعطل قيدًا لتجاوز خطأ بيانات.

## الاختبارات

شغّل اختبارات الوحدة والخدمات، ثم اختبارات UI offscreen، ثم UI runtime، ثم اختبارات لوحة المفاتيح والوصولية، ثم One-Folder، ثم Installer، ثم اختبارات المستخدم غير الإداري ودورة الحياة. اربط النتيجة بملف JSON أو تقرير جديد وبالهوية والزمن والمسار.

## التقارير العربية

استخدم قاموسًا عربيًا مركزيًا بدل النصوص المبعثرة. راجع العناوين والرسائل وأسماء الحقول والتواريخ والأرقام واتجاه RTL. لا تغيّر أسماء التخزين الداخلية لمجرد تغيير مصطلح مرئي إلا عبر قرار ومigration.

## تكامل الذكاء الاصطناعي في الإصدار الثاني

ضع واجهة `AiAssistantPort` اختيارية خلف طبقة Application، مع مزود محلي أو خارجي قابل للتبديل، وسياسة تمنع إرسال بيانات شخصية أو محتوى غير مصرح به. يجب أن يعمل النظام الأساسي دون التكامل، وأن تسجل كل مطالبة ونتيجة وفق سياسة خصوصية إن فُعّل التكامل.

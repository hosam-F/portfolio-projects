# ADR-3.13.38 — حدود الانتقال إلى وضع الإنتاج

## القرار

سيُجهز المشروع لمسار إنتاج عربي حقيقي، لكن لن تُلغى ضوابط سلامة البيانات والتتبع أو تُعتبر اختبارات الإصدار غير لازمة. يُفصل مسار الإنتاج عن مسار التحقق الاصطناعي بدل إزالة الحماية من المسار الحالي. تبقى بوابات المحتوى والإصدار حالات حوكمة تحتاج مراجعة موثقة في نهاية دورة الاستعداد، وليست مفاتيحًا يمكن تعطيلها لتجاوز دليل ناقص.

## السبب

المشروع الحالي مصمم فعليًا حول بيانات اصطناعية وسياق مستخدم تجريبي ومعرفات `TEST-*`. كما أن نموذج `UserAccount` الحالي لا يحتوي حقول اسم مستخدم أو تجزئة كلمة مرور أو جلسة إلكترونية. لذلك فإن تفعيل بيانات حقيقية أو كلمات مرور أو صلاحيات تشغيلية يتطلب تغييرًا معماريًا في التخزين والتطبيق والواجهة والتدقيق والنسخ والاستعادة. إخفاء الاختبارات أو فتح البوابات قبل هذه الأدلة قد يخلط بين نسخة تحقق ونسخة إنتاج ويعرّض البيانات للفقد أو الوصول غير المصرح.

## ما سيُنفذ لاحقًا

سيُصمم مسار محلي أولًا للحسابات يتضمن اسم مستخدم فريدًا، تجزئة كلمة مرور قوية مع salt، حالات الحساب، تغيير كلمة المرور، قفلًا بعد محاولات فاشلة، جلسة محلية قابلة للإبطال، وأقل صلاحية. ستُفصل أدوار المستخدم عن مراحل النمو التربوي، وستُربط الصلاحيات بنطاق المؤسسة أو الحلقة أو المجموعة عند الحاجة. لن تُحفظ كلمات المرور بصيغتها الصريحة ولن تُدرج في الوثائق أو الأدلة.

سيُصمم استيراد البيانات الحقيقية كعملية صريحة قابلة للمعاينة والتراجع، مع نسخة احتياطية مستقلة، وسجل مصدر وملكية وموافقة، وتحقق من الحقول، وفصل كامل عن fixtures الاصطناعية. لم تُقدم بيانات إنتاج أو بيانات شخصية لتنفيذها الآن، ولذلك لا يجوز إنشاءها أو تخمينها.

## ما لم يُنفذ

لم يُعدل Schema أو Domain أو Database Design في مرحلة الحوكمة. لم تُفتح `CONTENT_GATE` أو `RELEASE_GATE`. لم تُحذف ملفات أو قواعد بيانات أو حسابات Windows أو بيئات تطوير. لم تُلغَ الاختبارات التي تثبت سلامة التثبيت والاستعادة والصلاحيات؛ يمكن تقليل التكرار لاحقًا، لكن لا يمكن حذف الدليل المستقل المطلوب للإصدار.

## الحالة

`DECISION = APPROVED FOR DESIGN / NOT APPROVED FOR DESTRUCTIVE IMPLEMENTATION`  
`CONTENT_GATE = LOCKED / NO-GO`  
`RELEASE_GATE = LOCKED / NO-GO`  
`PRODUCTION_READY = NO`  
`RELEASE_READY = NO`

## الخطوة التالية

إعداد تصميم تفصيلي للمصادقة والصلاحيات وترحيل قاعدة البيانات، ثم مراجعة بشرية للحقول وسياسة الخصوصية والاستيراد قبل تنفيذ أي Migration أو استقبال بيانات حقيقية.
